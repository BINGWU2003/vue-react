# Vue 与 React 对照文档规划

本文整理已经确认的文档范围、章节结构、比较问题和后续示例要求，作为逐章完善正文时的依据。

当前交付为 Markdown 文档规划。章节中的示例与流程图均为后续待实现内容，本次只描述需求与预期观察结果。

## 1. 文档定位与范围

### 1.1 读者与目标

面向有 Vue 基础、希望系统学习 React 的开发者。以同一个需求在两端的实现方式为线索，解释 API 的使用、机制差异和选型依据，帮助读者建立 React 自身的心智模型。

文档需要回答三个层次的问题：

1. 遇到这个需求，在 Vue 和 React 中分别怎么写？
2. 写法为什么不同，更新、依赖、生命周期分别怎样运作？
3. 哪些经验可以迁移，哪些类比会导致错误？

### 1.2 技术基线

| 领域 | 文档约定 |
| --- | --- |
| Vue | Vue 3、Composition API、单文件组件、`<script setup>` |
| React | React 19、函数组件、Hooks |
| 示例语言 | TypeScript；类型用于帮助理解，不单独展开 TypeScript 教程 |
| Vue 路由 | Vue Router |
| React 路由 | React Router、TanStack Router |
| 全局状态 | Pinia 与 Zustand |
| 请求管理 | 仅讲 React：fetch、Axios、TanStack React Query |
| CSS | 普通 CSS、Scoped CSS、CSS Modules、Tailwind、动态样式、主题；简述 Sass 与 CSS-in-JS |
| 组件库 | 以 Element Plus、Ant Design 为例，只展开样式修改 |

React 的基线与当前项目的 React 19 依赖一致。Vue 生态与其他库的具体版本，在后续撰写相关章节时记录；涉及版本差异的 API 要单独标明前提。

### 1.3 已确定的边界

- 先规划目录、比较问题、示例与图示，再逐章完善正文。
- 默认章节提供 Vue 与 React 两端的对照代码；请求管理章仅提供 React 代码与演示。
- 后续 React 能独立演示的内容尽量提供可操作的预览，Vue 展示代码即可。
- 首期示例采用可阅读、可复制的代码与预览，不包含浏览器在线编辑器。
- Options API、React 类组件只在解释历史差异时简要提及。
- 不设“工程与进阶”章节，不展开构建部署、测试体系、SSR、水合、React Server Components、Next.js 或 Nuxt 教程。
- 保留日常开发所需的性能与正确性；组件库部分不展开通用组件 API 教程。
- 生态库按实际职责比较，避免把三个路由库或不同状态工具的 API 强行一一配对。

## 2. 整体目录与阅读顺序

按照“基础用法 → 日常项目 → 更新原理与常见误区”组织。前面遇到的机制先给出必要解释，第 11 章再统一串联。

| 07 | 状态管理 | 状态放在哪里，何时需要 Pinia 或 Zustand？ |

## 3. 各章比较问题与示例规划

### 01. 模板与 JSX

**本章目标：** 用相同的界面需求理解 Vue 模板与 React JSX 的表达方式。

| 比较点 | Vue 侧 | React 侧 | 重点问题 |
| --- | --- | --- | --- |
| 表达式与属性 | 插值、`v-bind`、模板自动解包 | JSX 表达式、属性与 props | 模板和普通 JavaScript 的边界在哪里？ |
| 条件显示 | `v-if`、`v-else`、`v-show` | 条件表达式、提前返回、CSS 隐藏 | 隐藏与卸载怎样影响状态和副作用？ |
| 列表 | `v-for`、`key` | `map`、`key` | key 表示什么，为什么不应随意使用索引或随机值？ |
| 事件 | `v-on`、事件修饰符 | 事件回调、事件对象 | 传函数与调用函数有什么差别，如何阻止冒泡和默认行为？ |
| 表单输入 | `v-model` | 受控输入、非受控输入 | 输入值由谁维护，双向绑定背后的数据流是什么？ |
| 类名与样式 | class/style 对象与数组 | `className`、style 对象 | 条件样式、内联属性和单位有哪些区别？ |
| 多节点内容 | 多根节点、template | Fragment | 如何组织结构而不引入多余 DOM？ |

**后续示例：** 可筛选的待办列表，包含新增、完成、隐藏与删除。React 预览可操作；两端代码表达相同需求。

**重点观察：** 条件卸载与 CSS 隐藏的区别；列表重排后的输入状态；受控输入怎样同步到状态。

### 02. 状态与派生数据

**本章目标：** 区分状态、派生值，以及不参与界面更新的可变引用。

| 比较点 | Vue 侧 | React 侧 | 重点问题 |
| --- | --- | --- | --- |
| 基础状态 | `ref` | `useState` | 修改值与提交一次状态更新分别意味着什么？ |
| 对象与集合 | `reactive`、对象类型的 `ref` | 对象/数组状态、不可变更新 | 为什么 React 中原地修改对象通常不能正确表达一次更新？ |
| 派生数据 | 普通计算、`computed` | 渲染时计算、按需使用 `useMemo` | 哪些值可以直接计算，什么时候才需要缓存？ |
| 连续更新 | 同步修改响应式值与更新调度 | 函数式更新、更新队列、批处理 | 连续三次更新为什么可能得到不同结果？ |
| 复杂状态转换 | 方法或组合式函数 | `useReducer` | 多个状态之间有约束时，如何组织转换？ |
| 不参与界面的可变值 | setup 作用域中的普通变量 | `useRef` | 定时器 ID、上一次值应该放在哪里，为什么 React 不能仅靠函数内普通变量跨渲染保存？ |
| 解构与引用 | `toRef`、`toRefs`、代理访问 | 每次渲染取得的状态快照 | 普通解构可能怎样影响 Vue 的响应式连接？ |

**后续示例：** 计数器连续加三、购物车总价、对象和数组更新、计时器 ID 的保存。

**重点观察：** 不复制保存可推导出的总价；区分“当前渲染捕获的值”和“可变引用中的最新值”。Vue props 解构等受编译器与版本影响的行为单独说明。

### 03. 副作用与生命周期

**本章目标：** 从“与外部系统保持同步”理解 React Effect，并与 Vue 的监听及生命周期机制比较。

| 比较点 | Vue 侧 | React 侧 | 重点问题 |
| --- | --- | --- | --- |
| 生命周期与同步 | `onMounted`、`onUnmounted` 等 | `useEffect` 的 setup/cleanup | 为什么不能简单把空依赖 Effect 当成 `onMounted` 的同义词？ |
| 显式依赖 | `watch` 的来源与回调 | `useEffect` 的依赖数组 | 依赖由谁声明，是否会自动追踪读取过的属性？ |
| 自动追踪 | `watchEffect` | 无严格对等的自动追踪 Hook | 自动收集到哪些读取，异步边界后又如何？ |
| 执行时机 | watcher 的 `flush`、`nextTick` | 提交阶段、`useEffect`、`useLayoutEffect` | 何时能读取更新后的 DOM，何时需要同步测量？ |
| 清理资源 | watcher 清理、卸载钩子 | Effect 返回的 cleanup | 依赖变化、卸载后如何解除监听和定时器？ |
| 闭包与依赖 | 响应式对象读取、watch 回调参数 | 状态快照、闭包、依赖比较 | 为什么定时器可能读到旧值，如何正确解决？ |
| 不需要的副作用 | `computed` 或事件处理 | 渲染时计算或事件处理 | 为什么筛选列表、响应点击通常不需要 Effect？ |
| 开发环境行为 | 调试时区分渲染和副作用 | Strict Mode 的额外检查 | 为什么开发日志可能多一次，怎样验证清理对称性？ |

**后续示例：** 定时器启停、窗口事件订阅、切换订阅目标、DOM 尺寸测量、闭包旧值与修正方式。

**重点观察：** 首次执行、依赖变化、清理、卸载的顺序。这里使用本地订阅或计时器；请求与竞态统一放入第 08 章，仅讲 React。

### 04. 组件设计与通信

**本章目标：** 围绕数据流、内容组合和必要的命令式控制设计组件边界。

| 比较点 | Vue 侧 | React 侧 | 重点问题 |
| --- | --- | --- | --- |
| 父传子 | props、`defineProps` | props | 如何理解只读约定与数据所有权？ |
| 子通知父 | `emit`、`defineEmits` | 回调 props | 事件参数、更新责任分别放在哪里？ |
| 可控组件 | `v-model`、`defineModel` | value/onChange 等受控接口 | 双向绑定如何展开成值与更新通知？ |
| 内容组合 | 默认插槽、具名插槽、作用域插槽 | children、内容 props、render props | 子组件怎样把内部数据交给外部决定显示？ |
| 跨层传值 | `provide`、`inject` | Context、`useContext` | 传递能力与响应更新的机制有什么区别？ |
| 命令式方法 | 模板引用、`defineExpose` | ref prop、`useImperativeHandle` | 聚焦、滚动等能力何时适合暴露给父组件？ |
| 状态提升 | 父组件持有状态并传递 | 父组件持有状态并传递 | 多个子组件怎样保持一致，怎样避免重复状态？ |

**后续示例：** 可控搜索框、支持自定义内容的列表、跨层主题切换、父组件触发输入框聚焦。

**重点观察：** React 19 的 ref prop 写法与历史 `forwardRef` 写法标明版本；Context 与全局状态库的职责在第 07 章继续讨论。

### 05. Composables 与自定义 Hooks

**本章目标：** 理解逻辑复用的执行上下文，避免把复用逻辑误认为天然共享状态。

| 比较点 | Vue 侧 | React 侧 | 重点问题 |
| --- | --- | --- | --- |
| 执行模型 | 通常在 setup 中调用组合式函数 | Hook 随组件渲染再次执行 | 哪些变量被保留，哪些计算会重新发生？ |
| 调用约束 | 生命周期与组件上下文约束 | Hooks 顶层调用与顺序规则 | 为什么不能按条件调用普通 React Hooks？ |
| 输入参数 | ref、getter、普通值及规范化 | 当前渲染的参数、依赖与闭包 | 参数变化时，内部逻辑如何收到更新？ |
| 返回接口 | refs、响应式对象、方法 | 当前值与操作函数 | 解构是否安全，返回引用是否稳定？ |
| 资源管理 | scope 清理、生命周期 | Effect cleanup | 订阅、定时器应由谁负责释放？ |
| 共享与独立 | 状态创建位置决定作用域 | Hook 内状态与外部 store | 两个组件调用同一逻辑，为什么通常得到两份状态？ |

**后续示例：** 复用计数逻辑、窗口尺寸订阅、两个组件分别使用同一逻辑、将共享需求迁移到明确的状态容器。

**重点观察：** 普通 React Hooks 依赖固定调用顺序；不把特殊 API 的规则推广到所有 Hooks。这里只覆盖当前约定的常规自定义 Hooks。

### 06. 路由：Vue Router、React Router、TanStack Router

**本章目标：** 以同一个小型应用比较三种路由方案的配置、导航和数据协作方式。

三方共同使用“商品列表 → 商品详情 → 编辑页”的场景，保留相同的路径、动态参数和查询条件。React Router 的示例写清使用的模式；数据加载部分以 Data Mode 为主要基线。

| 比较点 | 需要说明的问题 |
| --- | --- |
| 路由定义 | 路由树怎样描述，代码式与文件式组织分别属于哪种能力？ |
| 页面出口 | 嵌套页面怎样放置，布局与子页面如何组合？ |
| 动态参数 | 路径参数怎样读取、校验和传递，类型能覆盖到哪里？ |
| 查询参数 | 搜索、分页和排序如何与 URL 同步，默认值与序列化怎样处理？ |
| 导航 | 链接、编程导航、前进后退、替换历史分别如何实现？ |
| 加载状态 | 懒加载、导航等待状态、错误与 404 如何表达？ |
| 数据加载 | Vue Router 的导航前/后获取模式、React Router loader、TanStack Router loader 有何区别？ |
| 导航控制 | 导航守卫、重定向、路由前置校验、离开确认如何实现？ |
| 类型体验 | 参数和搜索条件怎样获得类型约束，各方案有哪些前提？ |
| 与请求缓存协作 | 路由负责何时加载，Query 负责哪些缓存与同步工作？ |

**后续示例：** 三方相同的列表与详情路由；React Router、TanStack Router 分别提供隔离的演示入口，避免预览争用站点 URL。

**重点观察：** 刷新后查询条件仍可恢复；后退按钮表现一致；导航控制无法替代服务端权限校验。Vue 侧只展示路由组织与代码，不延伸为 Vue 请求管理教程。

**选型输出：** 围绕已有项目生态、类型要求、URL 状态复杂度、数据加载需求列出选择依据，不预设单一优胜者。React 路由库的演示环境与当前承载文档的 Next.js 路由分开说明。

### 07. 状态管理：Pinia 与 Zustand

**本章目标：** 先判断状态归属，再比较全局状态库的组织与订阅方式。

| 比较点 | Pinia 侧 | Zustand 侧 | 重点问题 |
| --- | --- | --- | --- |
| 是否需要 store | 组件状态、提升状态、provide/inject | 组件状态、提升状态、Context | 跨组件共享到什么程度才值得引入 store？ |
| store 定义 | Setup Store、Option Store | `create`、state 与 actions | 状态与操作怎样组织？ |
| 更新方式 | 响应式修改、action、`$patch` | `set`、浅合并、不可变更新 | 嵌套对象更新有哪些差别？ |
| 派生数据 | getters、computed | selector、必要时显式派生 | 派生结果是否需要存回状态？ |
| 订阅粒度 | 响应式读取、`storeToRefs` | selector、相等性与引用稳定性 | 什么变化会让当前消费者更新？ |
| 组件外访问 | store、订阅接口 | `getState`、`subscribe` | 读取一次与持续订阅有什么区别？ |
| 持久化与重置 | 按需求选用插件或显式实现 | persist 等中间件、显式重置 | 哪些字段需要保存，什么时候清理？ |
| 状态边界 | UI/业务客户端状态 | UI/业务客户端状态 | URL 和服务端缓存为什么不宜全部塞进 store？ |

**后续示例：** 多组件共享购物车、按商品选择订阅、筛选状态归属、持久化偏好、重置状态。

**重点观察：** 展示一个局部变化影响哪些消费者；Zustand selector 返回新对象时说明稳定引用与相等性要求；不把 Pinia 的响应式访问机制套到 Zustand 上。

**选型输出：** React 全局状态只展开 Zustand；`useReducer`、Context 作为内置能力解释，不扩展 Redux 等其他全局状态库。

### 08. React 请求管理

**本章目标：** 分清“发出 HTTP 请求”和“管理服务端数据”，建立从手动请求到 Query 的递进关系。

本章仅讲 React，不提供 Vue、Vue Query 或其他 Vue 请求方案的平行实现。

| 层次 | 内容 | 重点问题 |
| --- | --- | --- |
| HTTP 基础 | 原生 fetch、Axios | 如何发送参数、请求头、请求体，如何解析响应？ |
| 错误语义 | 网络错误、HTTP 错误、业务错误 | fetch 为什么需要显式判断响应状态，Axios 的默认行为有何不同？ |
| 手动状态 | loading、error、data、empty | 首次加载、重新加载、空结果分别如何展示？ |
| 触发位置 | 事件、Effect、路由加载 | 什么动作应该触发请求，怎样避免把所有请求都放进 Effect？ |
| 生命周期 | AbortController、AbortSignal、cleanup | 参数变化或组件卸载后，怎样取消请求或忽略失效结果？ |
| 竞态与闭包 | 快速切换条件、延迟响应 | 为什么旧响应可能覆盖新结果，取消与提交结果校验如何协作？ |
| 客户端封装 | fetch 包装函数、Axios instance 与拦截器 | 哪些是传输层共性，哪些业务逻辑应留在调用处？ |
| Query 基础 | QueryClient、query key、query function | 缓存如何定位，影响数据的参数为什么要进入 key？ |
| 新鲜度与生命周期 | staleTime、gcTime、重新获取 | 数据过期与缓存回收有什么区别？ |
| 列表体验 | 分页、无限加载、占位数据 | 怎样避免切页闪烁，加载更多的数据如何组织？ |
| 数据修改 | mutation、失效、直接更新缓存 | 修改后应该重新请求还是更新已有缓存？ |
| 乐观更新 | 临时更新、回滚、同步 | 请求失败时如何恢复，怎样处理并发更新？ |
| 路由协作 | 预取、loader 与 Query | 怎样复用缓存，避免重复拥有同一份服务端数据？ |
| 与 Zustand 的边界 | UI 状态与服务端缓存 | 为什么一般不把 Query 返回的数据复制一份存进 Zustand？ |

**后续示例：** 商品搜索与分页、快速切换关键词造成的竞态、取消旧请求、两个组件复用同一缓存、更新后失效、乐观收藏失败回滚。

**重点观察：** fetch 与 Axios 是请求客户端，TanStack React Query 管理异步服务端状态，可以搭配使用。默认选项、自动重试和开发 Strict Mode 可能影响请求次数，示例需明确配置与环境。

**演示要求：** 使用受控的本地模拟数据与延迟，可切换成功、失败、空结果和慢响应；演示不依赖私人接口或外部服务可用性。

### 11. 更新机制、性能与正确性

**本章目标：** 用可观察的执行过程解释差异，再说明正确性和优化策略。

| 比较点 | Vue 侧 | React 侧 | 重点问题 |
| --- | --- | --- | --- |
| 依赖来源 | ref/代理访问、track/trigger | 显式状态更新、props、Context、外部订阅 | 是否会自动记录组件读过哪些对象属性？ |
| 组件执行 | setup 与渲染函数分别承担什么 | 函数组件在渲染时重新调用 | 哪一段逻辑重新执行，哪些状态能够保留？ |
| 调度与批量更新 | 响应式触发与更新队列 | 更新队列、批处理、调度 | 为什么数据修改与 DOM 可见变化不一定同步发生？ |
| 渲染与提交 | render effect、虚拟 DOM 更新、patch | render、协调、commit | 一次函数执行是否必然产生真实 DOM 修改？ |
| 父子传播 | 响应式依赖、props 与编译优化 | 默认子树渲染、props、Context 与优化边界 | 父组件更新后，哪些子组件会执行，原因是什么？ |
| 身份与状态 | 组件类型、位置、key | 组件类型、位置、key | 为什么列表重排或切换 key 会保留或重置状态？ |
| 计算与记忆化 | computed 与编译优化等 | 直接计算、memo、useMemo、useCallback | 缓存什么，代价是什么，何时确有收益？ |
| 引用与闭包 | 读取响应式对象、依赖关系 | 状态快照、函数/对象引用变化 | 不稳定引用会影响哪些依赖与订阅？ |
| 高频场景 | 列表、输入、组件边界 | 列表、输入、延迟更新等适用能力 | 何时减少工作量，何时需要虚拟列表？ |
| 观察与判断 | 组件更新与 DOM 变化分开观察 | 区分渲染、提交、Effect、Strict Mode 检查 | 怎样避免仅凭 console 次数判断性能？ |

**后续示例：** 父子组件执行记录、修改未参与显示的字段、重复设置相同状态、列表重排、切换 key 重置表单、昂贵筛选与缓存对比。

**必须讲清的概念边界：**

- React 默认不会像 Vue 一样，对组件读取过的对象属性自动建立响应式依赖图；但笼统说“React 不是响应式”容易掩盖两者都能由状态驱动界面的事实。
- React 状态更新会请求新的渲染。组件函数执行、子组件是否执行、是否提交，以及是否修改真实 DOM，需要分别讨论，不能概括为“整棵树和 DOM 都重新生成”。
- React 中一次渲染读取的是该次渲染的状态快照；调用 setter 不会改写已经捕获在当前闭包中的值。
- Vue 中普通组件的 setup 通常在创建实例时执行一次，组件渲染函数则由渲染 effect 驱动，可能多次执行。Vue 同样包含组件更新和虚拟 DOM patch。
- Vue 的底层响应式 effect、`watchEffect`、组件渲染 effect 和 React 的 `useEffect` 需要分别命名；React Effect 不承担组件渲染的同等职责。
- Vue computed 通常具有缓存与惰性求值特征，依赖变化不等于立即完成所有重新计算；React useMemo 是性能优化手段，程序正确性不应依赖缓存永不失效。
- React memo 也不能阻止所有更新；组件自己的状态、消费的 Context、props 引用与其他条件需要单独考虑。
- 优化先建立可观察的瓶颈与成本，再选择方案；不把 useMemo/useCallback 数量当成代码质量指标。

## 4. 不宜一一对应的概念速查

下表用于确定讲解关系，后续每节仍要以实际需求展开。

| Vue 概念 | React 中可比较的内容 | 必须补充的区别 |
| --- | --- | --- |
| ref/reactive | useState/useReducer | Vue 的响应式容器与 React 的状态快照、更新队列不是同一种机制 |
| 模板 ref | useRef、DOM ref | Vue 的数据 ref 与模板 ref 先分清用途，不能仅凭名称配对 |
| computed | 渲染时计算、useMemo | 先考虑直接计算；依赖收集、缓存方式和使用目的有差异 |
| watch | useEffect 等同步方案 | 没有统一替代关系；比较监听来源、执行时机、旧值需求和外部同步目的 |
| watchEffect | useEffect | Vue 自动追踪与 React 显式依赖不同，异步读取和清理也需要说明 |
| onMounted/onUnmounted | Effect setup/cleanup | Effect 的依赖变化会引发清理和重建，不能只按挂载/卸载理解 |
| nextTick | 提交与 DOM 读取时机 | React 没有可在所有场景直接替换的同名等价能力，围绕实际目的选方案 |
| v-model | 受控组件接口 | 两端都应说明值与更新通知的数据流，不能理解为 React 不支持表单同步 |
| 插槽 | children、内容 props、render props | 具名内容与向内容提供数据，可能需要不同组合接口 |
| provide/inject | Context | 都能跨层传递，但响应依赖与消费者更新方式不同 |
| Composable | 自定义 Hook | 执行模型、调用限制、闭包与清理上下文不同 |
| Pinia | Zustand | 比较客户端状态组织与订阅方式，不把响应式原地修改迁移成 Zustand 更新写法 |
| Scoped CSS | CSS Modules 等局部样式方案 | 作用域实现与全局例外方式不同，React 本身不提供 scoped 标签语法 |
