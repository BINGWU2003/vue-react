## 实际需求：父组件更新后发生了什么

先建立可观察的问题：修改显示字段、未显示字段、重复设置相同值，分别会导致哪些工作？不要先从 console 次数推断“重建整棵 DOM”。

<Diagram id="F01" />

Vue 通过 ref/代理读取收集相关响应式依赖，再触发 effect 与调度；普通组件 setup 通常在实例建立时执行一次，渲染函数由 render effect 驱动多次执行，同样经历虚拟 DOM 与 patch。React 默认不自动追踪组件读取了对象的哪些属性，状态更新请求新渲染，props、Context 和外部订阅也能带来更新。

不能简单说“React 不是响应式”：两者都可由状态驱动界面，但依赖来源、执行模型和更新边界不同。


<Demo id="E16" title="提交观察与 DOM mutation">修改显示字段，计数文本变化；修改未显示字段，React 有更新工作，但被观察区域不需要修改 DOM。重复设置相同值通常可跳过更新。开发环境观察 Profiler，生产默认禁用其计时回调；DOM mutation 计数仍可用。</Demo>

MutationObserver 统计的是被观察区域的 mutation records，不是渲染次数或严格的一次业务变更数量。Profiler onRender 表示一次已提交的分析回调，也不是组件函数每次尝试执行的记录。打开控制台筛选 E16，可分别看到 render Parent/Child、commit 后观察、Effect setup/cleanup。render 中的 console 仅用于调试，不是应放在渲染中的业务副作用。memo 子组件的字符串 prop 保持稳定，因此父级变化不必让它执行。

```vue title="Vue：分别记录 setup、render 与更新后观察"
<script setup lang="ts">
import { onRenderTracked, onRenderTriggered, onUpdated, ref } from 'vue'
console.log('setup：实例创建')
const count = ref(0)
const extra = ref(0)
onRenderTracked(event => console.log('track：开发调试', event.key))
onRenderTriggered(event => console.log('trigger：开发调试', event.key))
onUpdated(() => console.log('updated：组件更新后'))
</script>
<template>
  <button @click="count++">显示字段</button><button @click="extra++">未显示字段</button>
  <p>{{ count }}</p>
</template>
```

Vue 未在渲染中读取 extra 时，其变更通常不会触发这个渲染 effect；React 对应 setter 默认按组件状态请求渲染，而不是属性级依赖图。Vue 的 onRenderTracked/onRenderTriggered 为开发调试钩子，不作为生产日志机制。

## 父子传播与 memo 的边界

React 父组件重新执行时，默认继续计算子树；memo 可在 props 等条件满足时跳过部分工作，但不是所有更新的屏障。组件自身状态和消费的 Context 改变仍可更新；每次新建对象、数组和函数也会影响 props 引用比较。React 的协调、调度与 bail out 细节不等于“总是整树执行并重建 DOM”。

Vue 子组件更新与其响应式依赖、props 变化、编译优化等有关；不能说“Vue 父级永远不影响子级”。把渲染 effect、底层响应式 effect、watchEffect 与 React useEffect 分别命名：**React useEffect 不承担 Vue render effect 的渲染职责**。

状态更新与 DOM 可见变化可能不同步，两者都有调度和批量更新。React 当前闭包仍读取同一快照，setter 不会改写它，见 [连续加三](/docs/02-state#实际需求连续加三)。render 可以被重试或放弃，一次函数执行不保证进入 commit。

## 列表 key 与表单重置

<include lang="tsx" meta='title="rendering.tsx · 身份示例"'>../../components/examples/rendering.tsx#identity</include>

<Demo id="E17" title="稳定身份与状态重置">编辑第一行草稿后反转列表：稳定 id 让草稿跟着商品。切换索引 key 后重新编辑、反转，草稿会跟着位置。改变容器 key 则重建全部表单。</Demo>

```vue title="Vue：相同身份实验"
<script setup lang="ts">
import { ref } from 'vue'
import Row from './Row.vue'
const items = ref([{ id: 1, name: '笔记本' }, { id: 2, name: '钢笔' }])
const revision = ref(0)
</script>
<template>
  <button @click="items.reverse()">反转</button><button @click="revision++">重建</button>
  <div :key="revision"><Row v-for="item in items" :key="item.id" :name="item.name" /></div>
</template>
```

```vue title="Row.vue"
<script setup lang="ts">
import { ref } from 'vue'
const props = defineProps<{ name: string }>()
const draft = ref(props.name) // 刻意表示只取初值的本地草稿
</script>
<template><label>{{ name }} 的草稿 <input v-model="draft" /></label></template>
```

<Diagram id="F11" />

类型、位置和 key 一起影响实例身份。不要在父组件函数内部定义新的组件函数来规避 props 设计，它会在每次父级执行时创建新类型，可能重置状态。改变 key 是有意重置的方式，不是“强制刷新修复”的通用按钮。

## 昂贵计算与记忆化

<include lang="tsx" meta='title="rendering.tsx · 计算与缓存"'>../../components/examples/rendering.tsx#memo</include>

<Demo id="E18" title="昂贵计算与 useMemo">改变关键词，两端结果相同；点击无关状态，直接计算重新执行，useMemo 保留最近结果和对应计算耗时。计时受设备和开发检查影响，不能作为 Vue/React 排名。</Demo>

```vue title="Vue：按需计算与缓存"
<script setup lang="ts">
import { computed, ref } from 'vue'
const query = ref('1')
const count = ref(0)
const rows = Array.from({ length: 12000 }, (_, i) => `商品 ${i + 1}`)
const filtered = computed(() => rows.filter(name => name.includes(query.value)))
</script>
<template><input v-model="query" /><button @click="count++">无关状态：{{ count }}</button><p>{{ filtered.length }}</p></template>
```

computed 通常缓存且惰性求值，依赖失效不等于立即完成所有重算。React useMemo 缓存计算值，useCallback 缓存函数引用，memo 优化组件边界，三者都不自动收集属性依赖；不应依赖缓存永不失效来保证正确性。

本示例没有启用 React Compiler；若项目使用编译器自动记忆化，需要注明该前提并重新观察优化边界。缓存有依赖比较、内存和维护成本，廉价表达式不一定值得缓存。

## 高频场景的选择顺序

先用开发工具测出耗时在哪里，再减少不必要工作：让输入状态更局部、拆分昂贵子树、保持关键 props 引用稳定；昂贵非紧急 UI 可了解 useDeferredValue/useTransition，长列表考虑虚拟化。延迟更新不等于减少 HTTP 请求；搜索防抖、取消和缓存有各自职责。

检查稳定 key、对象不可变更新、Effect 依赖、订阅结果引用，再考虑优化。useMemo/useCallback 的数量不能衡量代码质量；组件函数执行也不代表真实 DOM 被全部重建。
